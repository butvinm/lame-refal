# Ущербный Рефал

> Потому что Рефал без поддержки перфокарт — это ущербный Рефал.
>
> @Mazdaywik

А ещё потому, что не работает большая часть IO-команд и падает от любого чиха.

Но! Его можно скомпилировать под WASM и запускать в браузере.

См. [examples/canvas](./examples/canvas/) и примеры на [GitHub Pages](https://butvinm.github.io/lame-refal/).

## Как это устроено

Компилятор Рефала-05 здесь не форкается и не патчится: он подключён подмодулем [Refal-05-Standalone](https://github.com/butvinm/Refal-05-Standalone) и используется как есть.
Репозиторию принадлежит только слой, которого не хватает для WASM:

* `runtime/include/` — заголовки стандартной библиотеки Си. Собираем с `-nostdlibinc`, поэтому `#include <stdio.h>` из `refal05rts.c` находит наши заголовки, а не системные. Исходники компилятора при этом остаются нетронутыми.
* `runtime/lamelibc.c` — их реализация поверх пяти импортов из JavaScript: `lame_write`, `lame_getc`, `lame_now_ms`, `lame_time_s`, `lame_exit`.
* `runtime/lamehost.js` — хост: импорты, маршалинг `argv`, снимок статической памяти.

Рефальская машина завершает работу вызовом `exit`, который на стороне JS бросает исключение. Чтобы `main` можно было звать на каждый кадр анимации, хост снимает копию памяти от нуля до `__heap_base` сразу после инстанцирования и восстанавливает её перед каждым запуском. Это заодно сбрасывает и аллокатор: его указатель — такая же статическая переменная.

Память больше не резервируется статически: модуль стартует с двух страниц и растёт через `memory.grow` по мере надобности.

## Сборка и запуск

Нужны `git`, `make`, компилятор Си (для раскрутки компилятора Рефала-05), `clang` с `wasm-ld` и `node` для тестов.

```shell
git submodule update --init --recursive
make
make serve
```

Первый `make` собирает компилятор Рефала-05 из подмодуля (около 15 секунд), дальше только перекомпилирует примеры.
`make test` прогоняет примеры вхолостую под Node и проверяет, что рефальская машина отрабатывает кадры без падений.

Готовый бинарник компилятора из [релизов Refal-05-Standalone](https://github.com/butvinm/Refal-05-Standalone/releases) можно подсунуть через переменную окружения:

```shell
REFAL05C=/путь/к/refal05c make
```

## Свой пример

```shell
./tools/build-wasm.sh examples/canvas/мой-пример main Canvas
```

Аргументы после каталога — список модулей для `refal05c`. Рантайм (`refal05rts`, `refal05bif`, `Go`) добавляется сам.

Две особенности, о которые легко споткнуться:

* функцию, которую передают замыканием (`<Map (DrawPoint 2) ...>`), нужно объявлять `$ENTRY`. Замыкание разворачивает `Mu`, разрешая имя по метатаблице **вызывающего** модуля: у `Map` это метатаблица LibraryEx, ваших функций там нет, и пройти проверку может только функция с признаком `entry`. Вдобавок, если в модуле нет ни одного прямого вызова такой функции, компилятор сочтёт её неиспользуемой;
* `<Arg 0>` — первый аргумент, переданный из JS в `program.run([...])`.

## Чего пока нет

Файловые операции (`fopen`, `fclose`, `fgetc`, `remove`) заглушены, поэтому `Card`, `Open`, `Get`, `Put` не работают. Чтобы их оживить, нужна виртуальная файловая система на стороне JS.

## Кредитс

Идея и подход к компиляции под WASM вдохновлены [zozlib.js](https://github.com/tsoding/zozlib.js).
