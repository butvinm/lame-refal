Ущербный Рефал

Рефал-05 компилируется в WebAssembly и запускается в браузере. Рефал-машина считает, страница рисует.

Потому что Рефал без поддержки перфокарт - это ущербный Рефал. @Mazdaywik

Как это выглядит

Правило клеточного автомата целиком: слева образец, справа результат. Компилятор Рефала-05 переводит такие предложения в C, clang собирает C в WebAssembly, а страница вызывает готовый модуль как обычную функцию. 

Rule {
  '111' = '0';
  '110' = '1';
  '101' = '1';
  '100' = '0';
  '011' = '1';
  '010' = '1';
  '001' = '1';
  '000' = '0';
}

Примеры

    Как это устроено

    Рефал-05 генерирует из программы код на C. Тот собирается под wasm32 без системной библиотеки: заголовки из runtime/include подменяют системные, а недостающие функции дописаны в runtime/lamelibc.c и частью уходят обратно в JS.

    Куча растёт через memory.grow, а free ничего не делает: память освобождается целиком между запусками. Поэтому рефал-машина не помнит ничего от вызова к вызову - состояние живёт на стороне страницы и ходит туда-обратно через аргументы и стандартный вывод.

    Файлов на диске нет, так что часть встроенных функций ведёт себя не так, как на обычной машине. Подробности - в README.

    Собрать у себя

    git clone --recurse-submodules https://github.com/butvinm/lame-refal
cd lame-refal
make
make serve

    Нужны make, clang с wasm-ld и node для тестов. Первый make собирает компилятор Рефала-05, последующие - только примеры.
